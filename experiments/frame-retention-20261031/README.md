# 实际接受帧的源端留存验证

本批次新增默认关闭的源端留存、任务端固定接受清单，以及独立文件审计。共享协议放在 `limo_evidence_protocol`；任务不依赖红色识别实现。

`dds-01` 是真实 ROS2 Jazzy / DDS 静态夹具：三个不同字节的无红色 RGB-D 输入各发布一次，经真实感知回调、处理元数据、Consumer/InspectionLedger、留存请求/回执和受控 writer 保存。采用系统时间及合成的精确时刻 TF；没有 Nav2、Gazebo、轮速或物理停车验证。检查点关闭后，三组实际接受的文件全部重新读取并验证，`audit.json` 为 3/3；`producer-shutdown.json` 与 `cleanup.json` 记录 writer、节点、executor 和 context 的关闭。

## 保留的失败与修复

- `producer-pure-01.log`：72 项测试中两个过短的测试专用 writer 启动时限失败。之后测试使用生产默认 5 秒，并在受控 ignore-TERM 场景确认 ready；生产时限未修改。`producer-pure-02.log` 为 71 通过、1 个 ROS 显式跳过，33.163 秒。
- `audit-counterexamples-01.json`：原 10 项文件审计测试通过，但独立反例证明错误的 consumer 回执身份、writer 状态和空窗口绑定仍会误报通过；null 输入另有未捕获异常。已补严格身份/绑定/类型检查和三个回归测试方法（共 13 项）。原反例文件不覆盖。
- `full-ros-01.log/.json`：458 项，10 个失败记录、1 个错误、1 个跳过，205.898 秒，exit 1；部分失败/错误属于同一测试或子测试，不能把这几个数字简单相减作为通过数量。记录器 dummy 未 ready、信号夹具等待/清理超时，以及旧 ROS 停车夹具的一次墙钟超时均保留。该轮加载了完整 F/C 仿真 underlay/overlay，环境脚本保留为 `full-ros-environment-01.sh`。源码前后哈希一致；该轮内的三帧存档实验确实通过，不代表整轮回归通过。
- `signal-cleanup-tests-01.log` 保留新增失败清理测试通过、原信号测试的 2 秒测试专用关闭时限失败。成功关闭场景随后使用生产默认 8 秒，另设 50 ms 故障场景确认明确返回未完成；`signal-cleanup-tests-02.log` 四项通过。最终身份记录覆盖关闭期间的检查点 worker，`signal-cleanup-tests-03.log` 两项受影响测试通过。失败时会先请求正常清理，再对已证明身份的自有 helper 做有界 fallback，并关闭管道。`fixture-process-audit-01.json` 在首轮结束后查到零个匹配残留，没有发送清理信号。

后续完整回归使用 `full-ros-environment-02.sh` 的独立 Jazzy 环境。原有录包和 ROS 停车测试的时限没有放宽；真实 ROS 启动子进程仅补上新共享协议的源码依赖。首轮日志支持“启动/等待前提未满足”，但不足以证明依赖搜索路径是每个失败的唯一原因。

`full-ros-02.log/.json`：460 项、3 个失败、1 个跳过，123.666 秒，exit 1；源码前后不变。新增留存用例及记录器测试通过，`dds-02` 再次保存并审计 3/3 原图，writer 和 ROS 资源均确认关闭。失败仍保留：旧连续目标夹具的首个停车窗口触及 2 秒截止；观察队列的取消 ACK 等待结束；两朝向各三帧已满足后，额外一次 sensor pulse 在目标退休过程中未于 0.2 秒内消费 TF。未将它们记为通过，也未调整生产停车、里程计或取消时限。独立阅读未发现留存默认关闭路径改变原控制行为，但不能仅据此排除所有调度问题。

`targeted-ros-03.log/.json` 单独复查这三项，3/3 通过（30.612 秒，exit 0），运行期间源码未变。相较第二轮只为独立 ROS 测试补上共享协议的源路径；测试行为和所有时限不变。这个结果不覆盖第二轮失败，不证明批量时序稳定。后续若调整测试，应区分任务真正截止与辅助等待跨越已退休窗口，不能通过放宽生产判据获得通过。

## 构建及使用边界

`build-01.log/.json`：三个包构建成功，源码前后不变。`installed-01.json` 核实六个关键模块来自当前 C 工作区，安装文件与源码逐字节相同。

原图留存与审计只证明固定接受清单、源端元数据和存储字节的对应关系，不能证明 TF 精度、完整视觉搜索、目标类别、召回率、物理静止或课程任务完成。run20 的历史缺图结果不因此改写。启用参数和预算见 [使用说明](../../docs/frame-retention.md)。
