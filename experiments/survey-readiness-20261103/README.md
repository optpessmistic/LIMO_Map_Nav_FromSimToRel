# 初始环视生命周期查询修复验证

修复单个 `GetState` future 永久 pending 后不再查询的问题；详见[设计与限制](../../docs/initial-survey-readiness.md)。本档案只验证查询逻辑和真实 ROS 服务行为，未启动仿真、Nav2 或速度发布器，不能算作 run33 重跑成功。

| 验证 | 实际结果 |
|---|---|
| Windows 纯逻辑 | 工具输出 chunk `370356`，退出 0；23 项通过，1 项原 ROS Action 用例因无 rclpy 跳过 |
| 新增纯逻辑案例 | 5 项通过：无响应重试、过期完成响应、请求时刻新鲜度、非 active/异常/不可用和单服务缺失 |
| 首次真实 DDS | 根会话 4801 退出 0；2 项断言通过，但退出有 `Destroyable` 清理警告，原日志和测试版本保留 |
| 清理修复后独立复测 | 根会话 63621 退出 0；2 项通过，3.623 秒，日志没有上述警告 |

第二轮首个服务回调故意延迟约 1.110 秒。超时后真实客户端移除并取消旧 future，新查询得到 active；旧 inactive 回应随后到达，仍只有一个响应被采信，active 证据未被覆盖。另一个用例持续返回 inactive，始终拒绝就绪。测试仅使用 domain 74 的独立随机服务名。

两次生产源码 SHA 均为 `3a3ce3bd5f39e5d9bfbfc34d185dc98a6bfd03858c02631eb9e9105ec7a86870`。复测只改变测试清理：释放已发请求的回调、限时处理剩余 future、检查异常，再销毁节点，不发新请求。两项清理检查均记录 pending=0、服务回调=0、异常=[]。首轮缺陷及其警告没有被复测覆盖。

`dds-first/` 和 `dds-cleanup-repeat/` 分别保存实际结果、完整日志、工具退出记录和当时测试源码。`source/` 保存最终生产/测试快照；`archive-provenance.json` 记录全部 16 份副本的原路径与哈希。`pure-tests.json` 是对实际工具输出的摘要及源码指纹，未保存纯测试的完整控制台日志；当时尚未创建新 DDS 测试文件，所以纯测试数量不含该文件。

原 run33 没有逐服务诊断，无法由本修复追认其具体失败节点或原因。下一次完整实验仍需通过预检查、实际库身份、建图、观察证据和返航验收。
