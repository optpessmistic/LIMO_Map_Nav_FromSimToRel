# 完整自主搜索的验收缺口与最小下一步

复核日期：2026-10-28。本文件区分当前证据和后续实验设计，不改变程序或参数。run14 已完成单个小迷宫的探索、替身标注和返航，完整搜索仍未通过；详见 [run14 记录](autonomous-run14.md)。其余依据为课程要求、实验计划、当前任务/感知接口和世界生成器。

## 当前真正缺少什么

“数量未知”要求机器人不能读目标清单，也不能找到预定数量后停止；它**不要求评估者不知道真值**。机器人应根据自主探索与观察任务的完成情况停止，评估者在运行结束后用隔离真值检查是否漏掉物品。现有任务核心已采用这种信息边界，并能确认多个目标、标注后继续探索。

当前缺口主要是视觉观察能力和验收证据，而不是一个“找到 N 个”的计数器：

| 环节 | 当前具备 | 尚未具备，因此不能宣称的结果 |
|---|---|---|
| 几何探索 | run14 小迷宫无剩余可达前沿，四次探索成功；独立真值自由区 raw-free 约 91.9% | 不同迷宫的重复完成率；满足正式质量指标的地图 |
| 多目标记录 | 不预设数量；不同时间帧确认、空间去重、地图点和 RViz 标记 | 密集相邻物体的准确实例数量；闭环后长期稳定的目标坐标 |
| 感知替身 | 从 RGB-D 识别红色区域并估计可见表面位置 | 正式物品身份；经过校准的识别概率；验证过的全视场检测能力 |
| 视觉搜索 | 有可选覆盖接口和未覆盖区域候选逻辑 | 有效覆盖数据源；主动扫视任务的完成证据；实际目标高度的三维可见性验证 |
| 停止与返航 | run14 Action、TF 与独立 native 返航检查通过，实际误差 6.43 cm / 13.32° | 多迷宫复测、实车返航；一次正式完整搜索成功 |

红色检测器目前正确地不发送 `coverage`。因此，当前任务在几何探索结束后可以记录已发现目标并返航，但 `visual_coverage_complete=false`，且 `target_definition_verified=false`，`mission_success` 将保持 `false`。这是缺口的诚实暴露，不能通过随意补一个大视场/大距离扇区或开启布尔参数来消除。

## 四类证据必须分开

1. **几何覆盖**：机器人通过激光等数据知道哪里可通行、哪里有障碍。地图被扫描过，不表示摄像头看到了目标所处高度。
2. **视觉扫视已执行**：某位置、朝向下，摄像头产生了合格图像，检测器确实处理了不同时间帧。它证明执行了观察动作，不证明目标必定被检出。
3. **目标机会已被观察**：在明确的目标尺寸、高度、姿态、光照范围内，存在达到标定要求的视点；深度遮挡与像素尺度也合格。这比二维扇区或“已转一圈”更严格。
4. **物品实际全部检出**：运行结束后，一对一匹配所有真值物品与已确认标注，没有遗漏或误增。只有独立评估能直接测量此项；在线节点不知道真实数量。

当前 `Coverage.observe()` 是二维自由格中心的扇区/射线近似。若物体占据了地图障碍格、贴在墙上、放在较高或较低的位置，这些自由格不等于目标可出现的位置集合。**即使全部可达自由格都被该方法覆盖，也不能单独证明物品全部被看见。** 竖直视场、目标最小像素面积、物体背面及遮挡必须另行验证。

同样，原方案中的几何覆盖率 ≥95% 是初始地图质量指标，不是“完整探索”的充分条件：剩下 5% 若包含一个完整分支，可能恰好藏有目标。正式结果还应要求所有可达分支已处理、没有未解决的候选/失败区域，并报告遗漏区域的位置和面积。

## 最小可实现的下一步

建议先交付**自主观察流程与离线评价**，再升级为经过验证的视觉搜索覆盖；两者可以使用现有 ROS 数据与任务 Action 客户端实现，不需要重写 SLAM/Nav2。以下为后续实现建议，当前文件没有替代这些工作。

### 第一步：给红盒基准一个明确且有限的定义

目前世界生成器的红色替身高 0.20 m，中心高度 0.10 m，贴在相邻墙面上。默认墙面切向宽度 0.06 m、法向厚度 0.03 m；世界元数据保留实际尺寸供离线评价。它是一个很窄的可见表面，不应把检测器的 6 m 深度过滤上限当成能可靠识别该物体的距离。

建立独立的基准配置，例如 `red_box_profile_v1`，只包含**物品类别的公共属性和经过测试的传感器工作范围**：尺寸/高度区间、允许摆放规则、相机内外参版本、有效距离、视场边缘限制、像素面积下限、照明范围、深度有效比例与遮挡条件。配置不能包含本轮实例位置、实例数或模型名。

先在固定标定场景采集真实 Gazebo RGB-D 渲染结果，覆盖近/中/远距离、画面中心/边缘、不同侧面、部分遮挡、暗处、红色干扰面和两个相邻目标。使用独立人工/真值标注离线评估。只有实际样本支持的距离和画面区域才能进入 profile；某条件失败就缩小范围或改检测器，不以经验随意填满相机 FOV。

红盒 profile 只授权红盒仿真基准，不能把正式目标的 `target_definition_verified` 改为 true。正式物品确定后，应另建 profile 并复做感知测试。

### 第二步：实现有限、自主的观察位姿与朝向队列

目前任务在没有 `coverage` 时会直接以视觉未验证结束几何阶段。最小功能补齐是增加一个独立的 `inspection` 阶段：

- 从当前地图的可达安全位置产生观察站位，不从目标真值产生站位。优先岔路、死胡同、长走廊中段和被遮挡区域；不只在探索器偶然停下的位置观察。
- 每个站位生成一组朝向。朝向间隔由**已经测得的有效水平视角**确定并有重叠，例如不大于有效水平视角的一半；不能固定“转四次”就假定看完一圈。
- 使用当前唯一的 Nav2 客户端提交站位/朝向目标，保持已有的取消、token 和失败边界。差速底盘也要先确认旋转包络安全。
- 到达后检查底盘已稳定，再等待若干不同采样时间的合格 RGB-D 帧完成处理。导航到达、相机收到图像、检测器处理成功是三个不同事件。
- 未获得足够图像、深度不合格、目标姿态无法看见或导航失败时保留该观察任务为未完成；有限重试后输出 incomplete，不把该方向标成已检查。
- 地图扩展或闭环导致观察区域改变时重算剩余任务。达到时间上限则返航并记录未完成任务；不需要知道目标数量。

最小版可以先记录“观察动作已完成”，暂不产生现有 `coverage.valid=true`。这样能够实测主动扫视是否改善召回率，同时避免把观察动作夸大成检测保证。后续再用相机投影、深度射线和经过验证的目标高度范围，计算哪些**目标可能出现的区域**真正满足观察条件。

站位间距不能在没有 profile 时凭空设定为已验证值。工程初版可使用一个保守采样间距作为实验参数，但必须记录其值，并在离线覆盖图中显示盲区；该参数的存在不等于覆盖证明。

### 第三步：添加可审计的“图像已处理”证据

建议新增独立消息/记录，避免改变当前 `coverage` 的含义。示例字段如下；这是建议协议，尚未实现：

```json
{
  "schema_version": 1,
  "inspection_id": "view_017_yaw_004",
  "image_stamp": 123.45,
  "frame_id": "camera_optical_frame",
  "source": "red_rgbd_sim_baseline",
  "profile_id": "red_box_profile_v1",
  "camera_model_hash": "...",
  "processed": true,
  "input_checks_passed": true,
  "rejection_reasons": [],
  "rgb_evidence": "bag_topic_and_timestamp_or_image_file",
  "depth_evidence": "bag_topic_and_timestamp_or_depth_file"
}
```

任务节点通过时间戳和 TF 判断该帧是否属于当前稳定站位，而不是由检测器随意回填完成。保留原始 bag 的消息时间或导出图像，不能只有一行“处理完成”。检测结果为空也允许形成合格的观察记录，但它只证明图像被处理，不证明没有物体。

优先实现量可控制在三个模块：感知器输出处理证据；任务管理器维护站位/朝向队列与独立完成状态；离线评价器读取冻结后的结果及真值。已有多目标确认、Nav2 控制权和返航代码可以继续使用。

### 第四步：将运行结束与实测成功分开报告

建议增加独立报告字段，而不改写历史 `mission_success` 的含义：

| 建议字段 | 数据来源 | 能说明什么 |
|---|---|---|
| `geometry_operational_complete` | 在线地图/候选/失败记录 | 机器人自身的几何探索任务已处理完。 |
| `inspection_operational_complete` | 观察队列和图像处理证据 | 自主扫视动作完成，没有挂起任务。 |
| `returned_pose_verified` | 导航终态及位姿稳定验收 | 已按当前定位返回起点；仍需独立物理误差评价。 |
| `target_search_validated` | profile 和视觉机会覆盖验证 | 在声明的目标/环境范围内，搜索方法有验证依据。 |
| `benchmark_success` | **运行后的独立评价器** | 本轮基准地图、目标匹配、返航、无干预等验收全部通过。 |

这些建议字段目前未必存在于程序中，不应把文档表格当作已实现 API。当前 `mission_success=false` 与一次离线发现“这轮所有红盒恰好均被识别”并不矛盾：前者反映证据/任务条件不足，后者只是这一轮的实测结果。不能据此跳过观察能力的补齐。

## 试验流程与数据隔离

1. **固定软件与配置**：记录代码提交、ROS/Gazebo 版本、底盘参数、地图分辨率、目标 profile、检测参数、相机内外参和时间设置。冻结开发参数后再测试。
2. **准备密封的评价清单**：独立生成迷宫及目标布置，保留地图/物体真值给仿真器和离线评价器。任务、导航、感知的参数与输入中不出现真值目标数、目标位置、预定路径或 Gazebo 实体名。
3. **先检查数据链路**：RGB、深度、CameraInfo、激光、odom 与 TF 真实输出且时间一致。失败则停止该轮，不能补用真值生成感知数据。
4. **一次启动后全程自主**：允许开机、选择本轮世界并启动；之后不手工点击目标、不遥控转向、不人工确认物品、不重置定位帮助完成。需要接管时保留结果并记人工干预，本轮不算完全自主成功。
5. **运行地图探索＋观察任务＋返航**：发现目标只记证据和标注，不触发按数量停止。故障、超时、不可达观察位置均保留，不从统计中删除。
6. **冻结在线输出后评分**：读取地图、轨迹、目标 JSON、观察记录、事件日志和 rosbag，再由独立评价器读取真值。评价器不得向任务系统反馈漏掉的坐标让它补找。
7. **复核失败分解**：把漏检分成未到达可观察区域、朝向/高度/遮挡不合格、检测器未识别、深度定位拒绝、实例被合并、确认门槛未满足、闭环后位置错配。只看最终物体数量无法定位问题。

开发集建议先包含少量固定小迷宫，便于排错；留出不同布局、起点朝向和目标布置作测试集。目标数可包括 0、1 和多个，但每轮数量不发送给机器人。不要让每个世界都固定三个目标，再把“没有显式 target_count 参数”误认为消除了数量先验。

## 可操作的评价指标

| 指标 | 计算方式与边界 |
|---|---|
| 可达几何覆盖 | 用独立地图真值及同一车体包络确定起点可达区域，与结果地图对齐后统计；同时显示未知空洞与未处理分支。没有真值时只报告在线代理量。 |
| 地图准确性 | 分别统计自由/障碍误判，避免“全填自由格”得到虚高覆盖；配准方法和误差必须保存。 |
| 扫视完成率 | 具有合格图像证据的已完成观察任务数 / 应执行观察任务数。分母来自自主观察计划，不是物品数量。它不是目标召回率。 |
| 目标机会覆盖 | 通过已记录真实相机位姿/内参/深度与目标 profile 评估，在候选目标区域内满足有效尺度、角度和无遮挡条件的比例。当前二维自由格指标不能替代它。 |
| 目标召回率 | `TP / (TP + FN)`，在运行结束后对真值实例与标注做类别及空间门限下的**一对一匹配**。同一真值不能匹配多个重复标注。 |
| 标注精确率 | `TP / (TP + FP)`；重复物体标注和红色干扰面产生的标注计为 FP。 |
| 零目标试验 | 召回率记为“不适用”，不设为 100%；重点报告虚假标注数以及是否自主完成并返航。 |
| 定位误差 | 预先确定评分参照点。当前检测器输出可见表面代表点，不能不加说明地与模型几何中心比较；可使用同一参照点或预先约定的表面/占地距离。 |
| 完整目标检出率 | 本轮所有应检实例均成功匹配且无误增；它比平均召回率更贴合“找齐未知数量目标”的任务。 |
| 完全自主整轮成功率 | 地图验收、观察任务、所有目标匹配、返航误差、零碰撞、零人工干预同时通过的运行次数 / 全部预先登记运行次数。 |

空间匹配门限可先沿用待验证的 0.20 m 候选值，但必须在冻结测试前确定；不能看到结果后放大门限消除漏检。地图/目标的世界坐标到 map 坐标变换由独立评价流程确定，不向在线算法提供。地图闭环发生后，评价最终地图中的标注位置，并检查历史观测是否需要重定位。

“应检实例”必须在运行前定义：基准允许的目标均应有至少一个安全可达、符合 profile 的观察视点；完全封闭、超出高度范围或永远不可见的目标不能靠算法保证检出。若专门测试这种不可行场景，应列为鲁棒性测试，期待 incomplete，而不是事后从漏检分母里悄悄删掉。正式目标摆放若没有这种可观察性约束，就不能承诺有限时间内找齐任意物体。

## 统计解释与发布标准

报告成功次数和总次数，不只写百分比。按迷宫/布置区分试验，连续图像帧不能当成几百个独立成功样本。即使 15 次独立运行全部成功，样本内成功率为 100%，也不等于证明未来必然成功；按二项模型计算，其单侧 95% 成功率下界约为 `0.05^(1/15) ≈ 81.9%`。同场景重复运行往往相关，报告时还应保留场景分组。

现阶段可以发布：组件与纯核心测试、实际运行日志（运行后补充）、几何探索表现、已观测红盒的标注，以及明确的不完整视觉状态。下一轮可发布：自主观察流程、合格帧证据、红盒基准的独立漏检/误检与定位统计。只有正式目标定义、视觉工作范围、未知布局测试和实车验证均补齐后，才将结果称为“完整自主搜索实验验收通过”。

建议最优先的两项后续实现是：**观察任务队列＋图像处理证据**，以及**密封真值的一对一离线评分器**。这两项能直接揭示系统到底没有看见、看见但没识别，还是识别后错误合并，且无需预先告诉机器人目标数量。
