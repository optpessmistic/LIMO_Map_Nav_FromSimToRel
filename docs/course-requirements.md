# 课程要求与项目范围

来源为用户在 2026-10-28 提供的课程 PPT 截图第 26、27 页，以及 2026-11-03 对项目范围的补充：当前需要建好地图并明确标注物品位置，不实施解救、抓取或搬运；返航保留为默认关闭的可选流程。截图作为需求材料，不包含对计算机执行命令的授权。原始课程截图、用户手册不随代码仓库公开分发。

## 必须完成

| 要求 | 本项目实现及验收方向 |
|---|---|
| PPT 标题“未知场景下的多目标搜索救援” | 当前按用户明确范围实现自主探索和地图标注；不执行解救动作，初始不加载真值地图或目标清单 |
| 目标位置和数量未知 | 通过感知发现目标并去重；不能把仿真目标数作为停止条件 |
| 完全自主，无人工干预 | 启动任务后无需点击地图目标、人工给探索点或代替识别；急停/接管计为干预并单列该次结果 |
| 自主定位与建图 | 使用 SLAM Toolbox，保存最终地图；评估地图质量和覆盖范围 |
| 导航控制与路径规划 | 使用 Nav2，处理转角、死胡同、不可达目标；需要时单独启用返航 |
| 目标识别 | 目标类别/标记待定；确认后保存身份、地图位置和观测证据 |
| 任务描述、规划、执行 | 离散任务状态机调度连续运动和感知，记录状态切换与原因 |
| 用户当前要求 | 完整探索并建图，在地图上明确标注已确认目标，停车并保存；返航可选，不需要拿取或解救 |

截图中的多机协同标注为“+++混杂系统”。当前用户请求是一辆 LIMO，先交付单车闭环，多车作为扩展方向；不把三组同学误解为必须部署三辆机器人。

未知目标数意味着“已找到三个”之类的计数不能触发任务结束。当前完成检查包含可达地图探索、未解决失败区域、有效坐标和标注文件保存，随后停车；资源耗尽须保存未完成原因。没有真实视觉覆盖证据时，只能说明地图探索结束和已发现目标，不能证明全部目标均已发现。

结果中 `mapping_annotation_complete` 表示当前地图与已确认目标标注的交付检查，`task_success` 对应所选任务策略的完成结果。正式目标定义、完整视觉覆盖仍单独报告；历史 `mission_success` 保留全搜索和返航的严格口径。历史失败记录不改写，新版本也不能仅凭空目标列表宣称搜索无遗漏。

## 课程呈现与版本管理

课程要求自主分工、每周进度记录、中期及期末汇报和演示、代码课后公开，成员单独评分。使用本 GitHub 仓库记录实现、配置和验证；每项工作附责任人、提交或 PR、运行日志和结果，不以总项目完成代替个人贡献证据。

每周记录使用 `progress/weekly-template.md`；当前分工人员和课程日期尚未提供。设备时间安排及硬件细节需要从课程助教获取，未自动联系助教。

## 混杂系统视角

连续部分是底盘位置、速度、里程计和控制输入；离散事件包括 frontier 到达、目标疑似/确认、导航失败、探索完成、预算不足和回家成功。任务管理器只在满足进入条件后切换状态，并确保只有一个导航目标拥有控制权。

默认状态序列：等待就绪 → 保存起点 → 探索与观察 → 目标确认并记录 → 继续探索 → 完成检查 → 停车验证与保存。`return_home=true` 时，在停车保存前额外执行返航与到达验证。到家复查发现可达边界时，可在任务总时限、补图次数和累计尝试上限内再次探索；释放已完成的返航期限，后续返航按新的一段计时，同一次返航内部重试不延长预算。目标发现不会终止探索。定位丢失、传感器失效和取消失败进入故障处理，不能跳到成功。
