# Run 5 原地转动后的地图错位调查

日期：2026-10-28。**已观察到近水平墙与约 −30°～−35° 的斜墙影相互穿插；根因尚未确定，需继续审计 scan、TF 与物理姿态的时间对应关系。** 单张栅格图不能区分扫描配准、外参、时间同步、运动估计或其他来源的问题，不能直接归因于某个 SLAM 参数。

## 数据与边界

Run 5 的初始 Spin 脚本报告 42.43 秒结束、`success=true`、`stop_verified=true`，其中 `stop_verification_source=wheel_odometry`。这些状态不等于地图质量通过。诊断在扫视结束后只读订阅 `/map`、`/scan`、`/mission/map_epoch` 和 TF；诊断工具本身没有启动 mission/perception，没有发送速度、导航目标或 action。场景中的感知节点由主任务另行启动，不属于本诊断的操作。

- epoch：`6e6f5908-6ded-41fc-a0a8-1f3c9361ad1a`。
- 地图时间：89.625 秒；`map → base_link` 时间：90.16 秒。
- 地图：86×58 格，分辨率约 0.05 m；范围 x=[−0.5263, 3.7737] m，y=[−2.2526, 0.6474] m。
- 当前地图位姿：x=0.28749 m，y=−0.00188 m，yaw=−0.57282 rad；此位姿只是待启动任务会记录的 home 候选。
- `map → odom`：平移约 (0.28749, −0.00188) m、yaw=−0.55491 rad；`odom → base_link` yaw=−0.01791 rad。朝向相加一致，但仅有 TF 内部一致性不能证明物理对齐正确。

原始地图有 1,953 个 free、634 个 occupied、2,401 个 unknown 格。后侧地图范围已扩展并出现占用点；由于墙影错位，不能仅凭这些点确认物理后墙已准确定位。

## 方法与结果

可视化直接绘制快照中的占据值，并叠加实际任务核心 `Grid.safe_cells(0.25)` 的四邻接安全连通分量、当前 TF 位姿及实际前沿。未知格和地图外仍阻塞；没有加入世界真值、改写地图、缩小半径或用先验填图。

| 检查 | 原始地图 | `.30 − .05 = .25 m` 启动区先验副本 |
|---|---:|---:|
| 起点 R=0.25 m 安全 | 是 | 是 |
| 起点足迹未知／图外／占用冲突 | 0／0／0 | 0／0／0 |
| 先验填充格数 | 不适用 | 0 |
| 起点安全连通分量 | 33 格 | 33 格 |
| 规划器状态 | `unreachable_frontiers_or_coverage` | 相同 |

全部 351 个安全格分为 **160、158、33** 三块。起点位于 33 格块，范围约 x=[0.09875, 0.64875] m、y=[−0.07756, 0.12244] m；158 格块甚至不属于起点的原始自由格连通分量。

起点的原始自由格连通分量共 1,156 格，有 14 个前沿。各前沿到起点安全块的最短欧氏距离均不小于 1.006 m，超过配置的 0.55 m 候选距离；到最近安全格的直线也未通过已知自由空间视线检查。因此当前无探索目标可以由地图连通性直接解释，不能归因于感知器未启动或启动先验不足。离线规划明确使用空视觉覆盖、`perception_ready=false`，并以原始地图提供观测证据。

另在原始自由格的四邻接图上计算最大瓶颈净空路径：每格净空取格中心到最近非自由格矩形的距离，路径评分取沿途最小净空，再最大化该评分。起点通向另一可连通安全块的最佳路径最小净空仅 **0.03536 m**，瓶颈格为 (37,38)，地图坐标约 (1.34875, −0.32756) m。图中的红线仅表示这条诊断路径，绝不是可执行轨迹。大量相互穿插的水平、斜向占用墙及这一净空量级表明，当前断开不宜解释为少量 0.05 m 栅格边界误差。

## 对任务失败语义的只读核对

对这份快照，任务核心报告 14 个未解决前沿、`unobserved_count=0` 且没有可执行目标。适配层会转入返航流程，原因是 `unreachable_frontiers_or_coverage_incomplete`；`map_complete=false`。若返航验收时仍是这些地图和覆盖证据，即使返航位姿验证通过，任务也不会成功。最终检查会重新读取新观测，因此这不是对未来地图状态的保证。这里没有实际启动任务或验证返航运动。

节点没有独立的墙形或全图配准质量检测器；`coordinates_valid` 只表示现有 epoch／跳变保护尚未使坐标失效，不是地图精度认证。小幅或渐进的地图修正也不会自动重新锚定历史 home 与目标。因此，本次失败报告是诚实的，但不能推导为“所有畸形地图都会被自动识别并拒绝”。正式验收仍需独立地图质量与目标定位评估。

## 运动中的输入对照（run5b）

同一模型、同一 SLAM 会话下再次执行受保护的 Spin，并在同一激光时间戳对齐原生测距、ROS `/scan`、`odom → laser_link` 和独立原生模型位姿。世界墙盒仅用于事后离线测距检验，不向机器人发布真值。此次延用了 run5 位姿图，不能当作新的 SLAM 冷启动复现。

`scan_motion_run5b.json` 保存 579 帧对齐扫描，其中 137 帧发生运动、共 98,640 束。原生与 ROS ranges 逐值相同；插值后的 world/odom 激光平面朝向最大差约 35.6 µrad，平面位置最大差约 0.068 mm。零时间偏移的测距 RMS 为 0.01298 m，±20 ms 为约 0.041 m，±100 ms 为约 0.141 m；进一步的 ±1 ms 对照仍是零偏移残差最低。这些结果未发现足以解释约 0.555 rad 修正的桥接、外参或明显时间错配，不代表证明绝对零延迟。

8 条运动射线的误差超过 0.1 m，最大 0.863 m，均紧邻预测深度不连续的遮挡边缘；未将其隐去。非边缘射线 RMS 约 0.01018 m，与配置的 0.01 m 噪声量级一致。诊断只验证本次视觉与碰撞几何一致的静态 box 场景；嵌套、其他几何或动态遮挡不能直接套用这个结论。

据 [SLAM Toolbox 2.8.5 的 Mapper::Process](https://github.com/SteveMacenski/slam_toolbox/blob/2.8.5/lib/karto_sdk/src/Mapper.cpp#L2508)，`use_scan_matching: false` 同时跳过连续扫描匹配与图匹配，适合作为下一轮隔离对照；它不是实车建图方案。只关闭 `do_loop_closing` 仍保留 `AddEdges → LinkNearChains`，不足以排除图近邻修正。下一轮在新模型实例、新 epoch 下仅改前一项开关，保留原始地图与真实运动证据。

相同 σ=.01 的前/后半段分别从新图开始：24/19 个接纳扫描，最大角修正 .01396/.00349 rad，最终平移约 .000532/.000305 m。相对对应 σ=.03 半段的接纳时间戳一致。半段只是同一噪声记录的不同初始朝向/历史检验，不能算新的独立实测。

## 新完整场景复验与采用范围（run8）

重新启动相同模型和 smoke 世界、使用新噪声序列与新 epoch `75ec6688-72e0-4b01-b94c-537b4f8d09d1`，仍运行系统原版 SLAM Toolbox 2.8.5；唯一 SLAM 改动为相关核 σ=.01。传感器/TF 与导航接口检查通过。真实车体最大累计转角 6.4070635 rad、最大漂移约 0.065 mm；最终 `map → odom` 为 yaw −.02094 rad（约 −1.20°）、xy=(.009489,−.001908) m。新的 137 帧运动扫描输入对照零偏移 RMS 约 .01383 m，未发现桥接偏移。

原始地图仍有 3 个起始中心未知格，包含当前位姿所在格；不能因此改写观测。独立起始碰撞先验仅填规划副本后，安全连通区 332 格、26 个 raw frontier，能选出有效平移候选，仍保留 `unobserved_count=3`。目前没有执行平移导航，也没有完成整张地图或搜索验收。

基于上述回放与新完整场景结果，项目的**小尺度迷宫仿真基线**采用 σ=.01。实车雷达、噪声和场景变化后必须重验，不能直接宣称已完成真实 LIMO 参数标定。另已识别原版占据栅格最大边界端点被裁剪的问题，该问题独立处理，不能通过给地图手工填墙来消除。
