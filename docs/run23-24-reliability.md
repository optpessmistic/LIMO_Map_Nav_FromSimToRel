# run23 / run24：启动时序、地图导出与导航阻断

两轮均运行 `9f682ac`，使用原 smoke 迷宫、ROS2 Jazzy、SLAM Toolbox 和 Nav2。地图导出及终态静止采集已有实测进展，但这两轮都没有完成自主探索和返航。原始日志时间为 2026-10-31，本文在 2026-11-01 整理。

## 本轮改动及验证

- 前沿观察站位优先搜索 0.55 m 范围，全部候选失败后才搜索至 0.8 m；安全半径、终点净空、视线与未知格处理不变。
- 经验证到家后的补探索，只允许从未启动的多朝向观察阶段首次启动；共享任务/返航预算不重置。
- 从已捕获的 OccupancyGrid 独立导出 PGM/YAML，并逐格回读；位姿图服务独立记录。没有把旧 `save_map` 失败改写成成功。
- 独立采集终态静止尾窗；某个导出失败仍保留失败并尝试后续步骤，所有步骤共用原绝对截止。

67 项规划/观察针对性测试、16 项地图导出测试、6 项收尾控制测试，以及一个真实 ROS2 启动用例通过。任务包构建通过，十个安装模块与源码一致；[该代码版本的 CI](https://github.com/optpessmistic/LIMO_Map_Nav_FromSimToRel/actions/runs/41205150648) 通过。冻结 run22 地图能选出距前沿约 0.673 m 的安全候选，但 run23/24 均提前失败，不能据此宣称扩大范围已完成真实导航验证。

## run23：参数响应超时

参数采集器未取得任务节点的 ListParameters 响应。按日志时间估算，请求早于 `Mission loaded` 约 0.276 秒；任务节点同时记录响应发送超时。支持启动/服务响应时序问题的推断，尚未证明具体 DDS 原因。

监督器取消了已发送的一个 frontier 目标并关闭所有自有进程组；任务退出检查确认目标终态和轮速计停稳。没有正常探索终态、没有接受图像，严格留存审计未执行，不能记作 0/0 通过。原始失败见 [run23 档案](../experiments/run23/README.md)。

## run24：启动通过，导航/TF 失败

运行器增加了等待 `Mission loaded` 后再创建参数采集器的顺序检查，等待上限 30 秒并受原总截止约束。参数请求 6 秒、参数阶段 17 秒以及任务、观察和返航预算均不变。本轮参数采集在 6.520 秒完成并通过。

第一个 frontier 目标被 Nav2 中止；RPP 日志报告转换请求时间 113.495 秒晚于最新 `map→odom` 的 113.450 秒。第二个目标随后因 `stale_base_tf` 被任务节点取消。没有完成停车图像窗口或返航。

原最终 JSON 的原因是 `frame_retention_failed`，而取消事件和观察关闭原因保留 `stale_base_tf`。这是取消期间派生留存失效覆盖原原因的诊断问题：本轮接受帧数为 0，producer 无写盘故障，不能解释成原图 writer 再次超时。原字段保持不变，后续修复单独验证。

独立 observer 也记录了延迟，而不只是任务节点报错：

| ROS 时间 (s) | TF 链年龄 (s) | 最新 odom 年龄 (s) |
|---|---:|---:|
| 113.598 | 0.148 | 0.003 |
| 114.300 | 0.725 | 0.705 |
| 114.594 | 1.019 | 0.259 |
| 114.625 | 约 0 | 约 0 |

中间两次 observer 采样的 wall 间隔约 1.885 秒，odom 接收也暂时落后。该证据支持公共数据传递或调度延迟，不能将根因限定为任务节点自身、SLAM 发布器或 DDS 某一处。下一步需将 `/tf` 原始消息和接收时间与主机调度对照；恢复后的新鲜 TF 不会撤销已经触发的安全阻断。

后续最小修复仅忽略“已进入 blocked 取消、且故障恰为 block 自身产生的 `mission_blocked`”所派生的 `frame_retention_failed`，保留首个原因。真实首次留存故障和 `cancel_timeout_stop_not_confirmed` 继续生效。19 项实际节点方法/真实留存对象的纯回归在 WSL 通过，包括等待目标接受、等待取消终态、真实留存故障与取消超时；未据此追认 run24 成功。首次 Windows 回归的一个既有文件用例因临时目录权限失败，原日志保留。
