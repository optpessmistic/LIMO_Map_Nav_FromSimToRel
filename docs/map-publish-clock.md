# run32 地图停顿与稳态发布实验

2026-11-03。run32 在第二个探索目标期间因 `map_stale` 主动取消并停止。它尚未创建观察队列，因此没有验证 0.15 m 观察点调整。第一个探索目标成功，并取得 3 组停车 RGB-D；标注 1 个红色替身。地图完成、返航及完整视觉覆盖均为 false，原严格留存审计因 `consumer_disabled_or_faulted` 失败。自有进程、独立停车尾段与 producer 退出检查通过，根进程仍以 1 退出。[原实验与失败记录](../experiments/run32/README.md)

## 什么数据过期

任务的 `map_stale` 判断是 `time.monotonic() - map_received > map_max_age_s`，本轮实际参数为 **5 秒单调墙钟**。`map_received` 在成功处理地图回调后更新；这不是检查 `/map.header.stamp` 的 ROS 年龄。故障取消事件的 ROS 时间为 162.859 秒。

闭合录包在 160.400–162.965 ROS 秒之间没有 `/map` 消息，共 **2.565 ROS 秒**，是本轮 293 条地图记录中的最大相邻接收间隔。两侧地图源时间戳为 160.250 和 162.875 秒，接收时的 ROS 年龄分别约 0.15 和 0.09 秒。同期其他话题仍有数据：

| 话题 | 该窗口记录数 | 最大相邻接收间隔（ROS 秒） |
|---|---:|---:|
| `/clock` | 2566 | 0.004 |
| `/odom` | 257 | 0.013 |
| `/scan` | 21 | 0.200 |
| `/tf` 中原始 `map→odom` | 267 | 0.021 |

TF header 在窗口内推进 22 次，严格推进之间最大接收间隔为 0.217 ROS 秒。独立 observer 在故障附近仍持有 header=160.250 的地图，但机器人 TF 年龄只有约 3–8 ms；随后地图恢复更新。observer 连续 TF 样本在录包间隔两端的 ROS 时刻附近对应约 5.30–5.52 单调墙钟秒，但不是地图回调精确接收时刻，不能由此重建任务的准确超时边界。

同一个控制器的两条日志时间从 1793704144.911 回到 1793704141.697，倒退约 3.214 秒。此前独立实测已确认本机 WSL 系统钟会回跳，并能延长 Jazzy `rclcpp::Rate` 的休眠，见[时钟对照](wsl-clock-tf.md)。本轮地图线程仍使用系统钟 `Rate`，而 TF 发布线程已使用 `WallRate`。

这些证据更支持地图发布分支停顿，而不是仅任务节点卡住。但地图线程还会等待 `smapper_mutex_`、重建网格和发布图；扫描回调入口推进也不证明每次扫描已完成优化。录包时间是记录器的 ROS 时间，不能替代独立墙钟或证明 DDS 未丢消息。**本轮未唯一确定 Rate 休眠、锁等待、计算和地图传输中哪一项导致停顿。** 输入哈希和逐话题结果见[闭合录包审计](../experiments/run32/analysis/run32-map-delivery-audit.json)。

## 后续最小修复

新增 `0004-slam-toolbox-steady-map-publish.patch`，只将 `SlamToolbox::publishVisualizations()` 内的 `rclcpp::Rate` 改为 `rclcpp::WallRate`。地图消息继续使用扫描 ROS 时间戳；本轮配置的 1 秒发布周期、5 秒接收过期阈值、网格计算、锁、任务预算与安全余量不改。它避免系统钟回跳延长该循环的休眠，不保证消除计算、调度或传输延迟。

获取脚本现在按固定顺序管理 `0002` 边界、`0003` TF 调度和 `0004` 地图调度三个补丁，接受精确的原版及逐级前缀；意外源码编辑会被保留并拒绝继续。四种前缀的临时 Git 夹具已验证只读检查、迁移、重复应用和意外文件保护。构建与后续运行必须分开记录；run32 使用的是只有 TF 调度修复的旧安装，不能记作 `0004` 的运行验证。

新独立安装已完成包构建，根会话 22504 退出 0。编译存在一次未来文件时间和 clock-skew 警告；后续 WSL 启动标识变化、原 `/tmp` 工作区缺失，使增量复核在编译前失败。另行检查的 20 个共享库依赖和 11 种服务原生类型支持通过，库目录 70 个普通文件哈希未变；这不等于增量编译成功，也不消除原警告。[构建与安装档案](../experiments/slam-map-clock-20261103/README.md)分别保留各项结果。

下一轮应加载新的独立安装，确认实际进程加载库的身份，然后重复完整探索、观察和返航。地图持续性、所有实际计划视图、新图像留存及返航须分别通过；不能仅凭补丁构建或有限观察队列完成宣称完整搜索成功。
